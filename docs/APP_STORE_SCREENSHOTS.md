# Carry Splits — App Store Screenshot Plan

## Capture Target

Use a current **6.9-inch iPhone simulator**, preferably iPhone 17 Pro Max, in portrait orientation.

Apple currently accepts between 1 and 10 screenshots per device family. If the user interface is the same across device sizes, the highest-resolution required screenshots can be scaled down by App Store Connect for smaller iPhones.

Capture screenshots as native simulator images with no transparency. Do not crop away the app UI unless required for final marketing composition.

**Screen:** Splits home screen with 2–3 realistic active splits.

## Screenshot Data Rules

Use fictional names and fictional expenses only.

Recommended participant names:
- Alex
- Jordan
- Sam

Recommended expenses:
- Dinner — $96.00
- Parking — $24.00
- Groceries — $63.00
- Train — $42.00

Do not use real personal data, private travel details, phone numbers, emails, financial-account information, or military/work information in App Store screenshots.

## Visual Rules

- Prefer Light Mode for screenshots 1–4.
- Use Dark Mode intentionally for screenshot 5.
- Keep the status bar clean.
- Use the same fictional dataset throughout the sequence where practical.
- Avoid excessive marketing text; let the UI remain visible.
- Do not imply bank transfers or payment processing.
- Do not display features that are not in v1.0.
- Do not show competitor names or logos.

## Capture Procedure

1. Boot the iPhone 17 Pro Max simulator.
2. Install the Release/Debug build with the same v1.0 UI.
3. Create the fictional screenshot dataset.
4. Navigate to the target screen.
5. In Simulator choose **File → Save Screen** or use `Command-S`.
6. Confirm the image contains no transparency and matches an App Store Connect accepted iPhone screenshot size.
7. Keep untouched originals in a local release-assets folder.
8. Export any final composed marketing screenshots as PNG or JPEG with no alpha channel.

## App Preview

No app-preview video is planned for v1.0. Apple treats app previews as optional, and the small utility scope does not justify delaying launch for a video.
